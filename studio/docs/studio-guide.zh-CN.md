# Hy-Nomas 本地世界工作室 · By T8star

> 以下为 0.2.0 完整包的功能、环境和实测记录。0.2.3 程序版仅提供程序文件；不随附 Python、模型和本地 evidence 目录。请先阅读 [程序版使用与自动更新说明](../README.zh-CN.md)，在线模型和实际视频见 [Hugging Face](https://huggingface.co/t8star/HY-Nomas-Comfy)。

Windows 粉白色本地界面与原生 ComfyUI 节点，使用同一 Python 推理核心。目标配置为 NVIDIA 24GB 显卡、64GB 系统内存。

**0.2.0：完整界面交互、文字/续接/图片起始、原生默认高清、独立高清与三种模型路径的移机推理均已通过本机验收。原生节点在宿主进程内执行；正式包运行代码与已验收候选一致。逐条证据见 roadmap.md 和 evidence/。**

## 启动

1. 完整解压到可写目录，优先放在空间充足的 SSD。支持路径含空格、中文。
2. 包含完整 runtime 的发行包直接双击 `启动整合包.cmd`；缺少环境时先运行 `安装环境.cmd`。
3. 在浏览器打开 `http://127.0.0.1:7866`。启动窗口保持开启。
4. 在“模型与运行状态 → 模型路径设置”复用已有权重，或运行 `下载模型.cmd`。
5. 三个模型就绪后，从短片与轻量分辨率开始。修改动作或场景变化后可继续生成；“导出完整视频”合并已完成片段。

粉白色配色参考用户指定的 IndexTTS 2.5 启动界面。页面顶部与底部显示 By T8star。

## 模型路径

支持三种方式，均直接读取模型所在位置：

| 配置 | 行为 |
| --- | --- |
| 全部留空 | 使用本包 `models/diffusion_models`、`models/vae`、`models/text_encoders` |
| 模型根目录 | 可指向已有 ComfyUI 的 models 目录、官方 HF 模型目录或平铺目录 |
| 单独填写模型文件 | 三个权重可放在不同磁盘，分别填写完整文件路径，优先于根目录 |

使用模型清单中的 INT8 DiT、FP8 PixelUMM 和 Qwen2.5-VL-7B FP8 scaled。文件名可以改名，保留 `.safetensors` 扩展名；改名后使用单文件路径。目录扫描只匹配清单中的标准名称和官方布局，不会搜索整个磁盘。

路径保存在 `config/model_paths.json`，重启自动恢复。相对路径以整合包目录为起点。外部绝对路径在整合包移动后仍指向原位置；迁移到另一台电脑时需重新设置。点击“恢复默认路径”即可恢复包内布局。

错误路径明确显示，不会悄悄改用另一份模型。文件大小或格式不符会阻止加载；运行 `校验模型.cmd` 可对所选模型做完整 SHA256 校验。保存路径时的快速检查不代替完整哈希校验。

生成中或已有世界历史时不能更换路径。先导出视频、重置世界，再更换模型。下载器也会读取已保存的路径；已有文件不匹配时保留文件并报错，不直接覆盖。

## 原生 ComfyUI

双击 `启动ComfyUI原生节点.cmd`，访问 `http://127.0.0.1:8189`。模型目录根据上述配置自动生成；在各加载器中选择实际文件名。

可单独将 `custom_nodes/ComfyUI-HyNomas-T8` 放进自己的 ComfyUI/custom_nodes，模型路径沿用宿主的 `extra_model_paths.yaml`。需要 ComfyUI 0.42+、兼容的 PyTorch/Triton；Windows 建议采用整合包固定环境。请不要同时安装本派生包与原版节点，以免相同节点 ID 冲突。

导入 `custom_nodes/ComfyUI-HyNomas-T8/workflows/T8 - Budgeted world.json` 开始。节点直接执行模型、标准 KSampler、历史缓存与解码，接入 ComfyUI 模型管理。独立界面也在本进程调用同一核心；不向另一个 ComfyUI/模型服务转发推理。

ComfyUI启动后更改模型路径设置，需要重启该入口并重新选择文件。自定义目录与默认目录存在同名文件时，自定义目录优先；下拉框保留改名文件。
原生入口启动前会检查显式自定义路径；已保存的目录或文件失效、大小不符或文件头损坏时，明确停止启动，不隐式改用包内同名模型。全默认且尚未安装权重时仍可打开宿主配置模型。

详细节点说明见 `custom_nodes/ComfyUI-HyNomas-T8/README_T8.zh-CN.md`。不要同时在两个界面进行 GPU 生成。

## 内存与会话

- 24GB 预设：INT8 DiT、FP8 解码器与文本编码器，分阶段由 ComfyUI 管理模型驻留。
- 首次加载要求约30GiB可用系统内存。建议只启动当前使用的入口；空闲的ComfyUI宿主也会占用内存。
- 默认 CPU KV 历史预算为 12GiB；这不包含模型、输出帧或其他程序占用，不等于进程总内存上限。
- 达到预算后导出并重置，或在确认有足够系统内存后调高预算。历史窗口限制不会删除完整 CPU 档案。
- 取消在采样或解码窗口间响应，可能需要等待当前 GPU 操作结束。成功写出的片段保留，未完成片段不提交。
- Windows入口会在加载PyTorch前设置内存回收参数；真实短片重置后进程RAM从约21.8GiB保留降至1.37GiB。外部ComfyUI请参阅节点说明的启动环境配置。
- 首次运行需要编译 GPU 算子。速度、显存上限以本机验收结果为准。

图片起始只用于新世界。场景编辑模式先以0.5秒静止图片写入历史，再生成所选时长的动作；导出时保留一帧起始图片。结构化 JSON 模式需至少两段：第一段描述静止图片并指定其历史时长，后续段落描述运动。

## 下载、诊断与输出

`下载模型.cmd` 从清单固定版本下载，按区块续传，完成后验证 SHA256。`.partial` 与 `.ranges.json` 是下载进度，未完成时请保留。默认不下载不需要的 PE、FP32 大模型、训练数据或 LoRA。

`环境诊断.cmd` 将环境、GPU、内存、路径状态写入 `evidence/diagnostics.json`。运行日志位于 `logs/`；视频和会话 JSON 位于 `outputs/<会话ID>/`。重置不删除视频。所有推理所需 tokenizer 文件由本地 ComfyUI 提供；推理设为离线。

中文安装路径下，CUDA编译缓存会优先使用Windows短路径；磁盘未启用短路径时，自动放到同盘的 `T8star-HyNomas-cache` 英文目录，避免CUDA/Triton的路径编码限制。实际位置记录在 `cache/compiler-paths.json` 和环境诊断中。它只存放可重新编译的缓存，模型路径继续使用你指定的位置。

## 本机实测记录

RTX 5090 Laptop 24GB / 64GB RAM，INT8 DiT、FP8 PixelUMM、FP8 Qwen，8步 euler/simple、CFG 1。

| 场景 | 实际输出 | 本次总耗时 | 整卡采样峰值 |
| --- | --- | --- | --- |
| 文字起始，单入口冷加载 | 640×384，1秒/24帧 | 109.9秒 | 19.69GiB |
| 同一进程续接并转动镜头 | 640×384，新增1秒/24帧 | 34.1秒 | 20.32GiB |
| 高清文字起始，当前版本 | 1280×704，5秒/120帧 | 208.2秒 | 15.91GiB |
| 原生默认双段，当前版本 | 1280×704，10秒/240帧 | 352.5秒 | 17.53GiB |
| 图片起始 | 640×384，25帧 | 88.3秒 | 19.63GiB |

耗时包含准备、加载、采样、写入历史与解码。另一次冷加载短片耗时499秒，系统/缓存状态影响明显；不承诺固定速度。NVML数字为整卡采样，包含背景占用；本次高清复测采用当前分阶段卸载策略，历史175.4秒/23.80GiB记录仍保留。首次加载、编译及内存/磁盘状态会显著影响速度。

图片起始复测最低可用RAM15.84GiB，完整界面最低可用RAM11.10GiB。当前独立高清最低可用RAM7.54GiB，原生默认双段最低可用RAM8.15GiB，均超过4GiB验收门槛。此前双段解码仅余2.39GiB的失败记录保留在 evidence/failures/；完整输出预留和宿主缓存引用修复后，当前版本已通过真实复测。

移机实测使用全新中文/空格目录与包内Python：默认路径24帧、自定义外部根目录24帧、独立改名文件及图片起始25帧，均完成真实推理、导出、重置和至少4GiB物理RAM余量检查。三次最低可用RAM分别为13.57、12.86、11.28GiB。48,412个归档成员生成前后的CRC及候选SHA一致，Python和模型模块来源均在解压包内；详见 `evidence/relocation-acceptance.json`。三份原始模型在硬链接切换后再次完整SHA256匹配，见 `evidence/models-verified-final.json`。

正式打包再次验证实际执行图、完整帧数、当前宿主启动代码指纹和资源门槛，并逐项比较已验收候选的运行代码/环境。允许更新验收记录、Markdown和发行版本状态，禁止用未经实测的代码替换候选。ZIP写出后逐文件检查CRC并生成 `.zip.sha256` 校验文件。

`evidence/sample-native-default.mp4`、`sample-standalone-hd.mp4` 与三个 `sample-portable-*.mp4` 是本次真实样例。整合包包含完整运行时，模型权重单独下载或通过路径设置复用已有文件。
